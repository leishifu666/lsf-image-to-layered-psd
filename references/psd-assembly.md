# PSD 堆叠与验收

在写入或修复分层 PSD 时读取。本文件不限定库或平台；以下约定必须针对当前工具核实。

## 图层面板、写入数组与合成顺序

建立一份独立于库的“图层面板从上到下”清单。该清单记录可见性、组路径、局部遮挡/蒙版及元素 ID，作为组装基准。

- Photoshop 面板中上层遮挡下层。常见的从后到前合成算法，绘制顺序与面板顺序相反。
- API 的图层数组不一定使用面板顺序。查当前官方文档或实现，核对根节点和组内数组，不能凭经验猜测。
- 如使用 `ag-psd`，不要只依据 `README_PSD.md`：已实测 **31.0.3 的 `children` 为从后到前**，根节点与组内相同；其 README 描述与实际实现不一致。`psdWriter.ts` 的 `addChildren` 按数组顺序写入，独立读取器 `psd-tools 1.25.0` 与 Photopea 确认最后一层在前。`build-editable-psd.cjs` 接收面板从上到下清单，在写入边界递归反转；读回后也转换顺序。其他版本仍须核实，不能沿用未经验证的约定。
- 部分库不会根据图层变化自动更新内嵌合成图和缩略图。修改图层后必须更新这些派生图，或按该库已验证的方式省略；旧缓存不能作为正确显示的证据。

如果数组约定尚不明确，用局部重叠的两个纯色图层写一个小型测试 PSD，通过可信读取器或 Photoshop 核对前方色块与图层面板顺序。此测试只能确认序列化行为，不能代替目标图片的遮挡检查。

## 分组与局部遮挡

先建立全部元素的正确堆叠顺序，再考虑分组。属于同一类别的元素可能位于不同深度；不能用固定类别组把它们全部移到其他元素上方或下方。只有不会破坏全局遮挡关系的连续图层适合归入同一组。需要在其他图层两侧分别显示的子图层，分别放在对应位置，并使用关联命名；不要为收进同一组而移动它们。

核对组的可见性、混合方式、不透明度、剪贴和蒙版。若不能确定复杂组是否保持原图效果，使用更简单且可验证的图层结构。普通文字按 [ps-editable-text.md](ps-editable-text.md) 和 [font-verification.md](font-verification.md) 执行字体核验与原生编辑；不擅自增加无关的矢量或复杂智能对象重建。

## 保存后检查

1. 重新打开保存的 PSD，核对实际面板顺序、组内顺序、可见性、尺寸和坐标。
2. 从读取出的真实图层、Alpha、蒙版与混合设置重新合成，忽略内嵌合成缓存进行这项检查。所用渲染器必须支持文件实际使用的特性；不支持时不能报告该特性已通过。
3. 对照原图的遮挡清单，逐个查看交叠区域。不能只比较同一实现写入前后的像素值，否则可能重复使用同一种错误约定。
4. 分别隐藏前方元素，确认露出的后方区域已经补全，且其他图层没有该元素残留。检查补全区域恢复可见性后不会穿到前方。
5. 导出这次图层重合成的预览。普通 PNG 读取器只读 PSD 合并图时，不能据此验证排序；名称和编号正确也不能证明实际排序正确。

报告分别列出文件解析、实际图层重合成与 Photoshop 首次打开实测的结果。未在 Photoshop 中打开时明确说明，不把读取器检查称为应用实测。

遇到内孔填满、图层样式不符、脚本启动后无产物，或独立读取器不支持原生效果时，读取 [ps-compatibility.md](ps-compatibility.md)。按实际版本定位；缓存预览、脚本退出码和同实现读回均不能单独证明实际 PS 显示正确。

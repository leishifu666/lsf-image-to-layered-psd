# Photoshop 执行与兼容性排查

仅在实际 PS 脚本执行、PSD 路径/样式或独立渲染异常时读取。以下线索来自 Photoshop 27.0.0、`ag-psd 31.0.3` 与 `psd-tools 1.25.0` 的具体实测；其他版本先查当前实现并做受影响功能的小样验证，不直接套用。

## 分开判断执行、变更和读回

- 启动进程成功或退出码为零不等于 PS 执行了脚本。记录进入脚本、目标文档/图层、变更完成、保存、重开和导出阶段；核对新产物、时间和实际内容。出现“JavaScript code was missing”且没有进入日志时，排查调用入口、脚本路径和编码，不报告制作成功。
- 在本次工作环境验证过的脚本调用方式不能当成通用修复。本次调整路径、编码或脚本头后能运行，只证明该组合有效；未逐项隔离就不能断言某一项是根因。ExtendScript 使用其实际支持的旧版 JavaScript 语法，避免保留字（例如曾触发解析错误的 `native`）及未验证的新语法。
- 逐层变更前明确目标文档和活动图层，再读取边界或移动；不要依赖上一次选择。保护用户已打开文档，改字与效果验证使用另存副本。
- 写入返回后读属性失败，先检查变更是否已发生，再决定是否重试。曾实测渐变方向写入成功、随后读角度报错，而保存重开与独立 PSD 数据确认新方向已写入；该读回失败的根因未确定，不能推断零值必然被省略，也不能重复写入后称首次失败。
- 可复用自动化脚本将输入/输出路径、目标图层 ID、字体与样式参数放进配置，按稳定 ID 执行并输出阶段结果。海报专属坐标、固定文字层数、机器字体路径及一次性任务脚本不直接收进 skill；参数化也不能代替验证具体 API。

## 路径和图层样式：缓存正确仍需看 PS

- 含内孔的复合路径可能在 Canvas 缓存中正确，在实际 PS 中填满。`ag-psd 31.0.3` 的一次嵌套字形轮廓测试中，`combine` 未得到预期孔洞，核对轮廓后使用 `exclude` 才恢复；这不意味着所有形状都应改为 XOR。按实际嵌套关系选择布尔操作，检查 0、8、字母内孔与重复路径。
- 同版本一次投影写入产生空名称、空曲线的 `TrnS` 轮廓，PS 显示不符；设置有效线性轮廓后恢复。写样式时核对当前库支持的完整字段和默认值；本次有效的线性轮廓为 `name: 'Linear'`、`curve: [{x: 0, y: 0}, {x: 255, y: 255}]`。不要只检查序列化没有报错。
- 原生文字描边、删除线、简单斜体等在 PS 保存后可继续编辑，不需要先轮廓化。复制图层样式前核对实际效果，改字后检查效果跟随，不能用顶层预览遮住真实错误。

## 独立读取器的渲染能力不足时

先判断异常来自 PSD 还是读取器：`psd-tools 1.25.0` 的一次强制绘制对原生渐变和描边显示不符，实际 PS 重开正常。不能把读取器失败算成验收通过，也不能仅据此断言 PSD 损坏。

优先使用支持实际特性的独立渲染器。确实不能独立完整绘制时，可分别记录以下证据：

1. 实际 PS 从保存重开的 PSD 导出正式预览，并逐层导出真实 RGBA；导出要保留真实定位、效果和 Alpha。
2. 独立读取器忽略内嵌合并图，解析真实图层 ID、面板顺序、可见性、不透明度、混合方式和蒙版，按 ID 关联导出文件。
3. 仅对已经支持的合成语义独立重合成，检查定位与遮挡；不透明度、效果及蒙版只能应用一次。遇到剪贴、跨层混合、调整层、复杂组或依赖下层的效果，不将独显 PNG 简单叠加冒充完整验证，应换用支持的渲染流程或明确缺项。

报告写明“PS 负责图层渲染，独立流程检查结构与合成”，不能称独立读取器已完整绘制全部原生效果。记录比较尺寸、Alpha/颜色处理、误差指标及差异图；小合成误差只证明两种合成结果一致，不证明字体匹配原图或位图细节保真。该方法不读取合并缓存来伪装真实图层检查。

# 独立元素并发调度 · PS

先按主入口分流。普通文字、能准确还原的纯色/渐变/规则形状采用 Photoshop 原生方式，不为凑队列再生图。查看原图后建立稳定 ID、区域、锚点、统一倍率、输出路径、制作方式和遮挡清单。

参考与依赖已满足的独立生图任务默认一起提交；一个请求只处理一个元素，不把多个元素画进一张图冒充拆层。字体研究、候选试排和原生排版准备可与位图任务并行。本流程不要求子代理。

不人为设置固定槽位或小批次。只有用户明确限并发，或工具/服务存在已确认限制时使用相应上限并说明。全量提交不表示服务无限容量，也不保证速度按并发数增长。不能擅自更换模型、接口或供应商。

需要时使用 scripts/element-pool.js 的 runElementPool(tasks, execute)：默认 concurrency 为 all；只有有依据的限制才指定有限值。结果按 ID 保存，失败隔离，保存回调错误不会丢弃已返回素材。execute 负责按实际工具契约生成；队列不自带请求或自动重试。所有 Promise 都必须等待，不能结束执行单元而遗失生成结果。

使用 API 时可运行 scripts/image_api.py --config CONFIG --jobs JOBS --output-dir DIR；默认同时提交已准备的独立元素。限流时保留已成功素材，仅按实际限制处理明确失败项；超时或结果未知先核对服务记录和产物，不能盲目重跑扣费。生成后保存失败时优先恢复 recovery_file，不重新生图。

保留真实 Alpha、毛发和半透明边缘；统一阈值裁剪不能替代检查。素材按统一坐标和锚点落位，不分别居中。PSD 由一个写入流程按遮挡清单组装，不能按请求完成顺序排序；普通文字和原生填充/形状保持可编辑。

分别记录生图、重试、组装和验收的实际耗时，不为测速另生成无用图片，也不把提交完成称为制作完成。最终预览来自实际保存的 PSD 图层。
